# Acceptance checklist

Test with approved documents on the intended deployment. Record the date, tester, run IDs, relevant logs, and pass/fail result. Do not use an automated unit-test pass as evidence of real model quality or deployment isolation.

## P0 - required before operational use

- [ ] **Clean installation:** start with an empty database and storage directories. Vault, runs, reports, and search must be empty. No example findings, charts, replay buttons, synthetic metrics, or sample exports appear.
- [ ] **Legacy cleanup:** stop the backend, preview the cleanup script, then apply it to the intended database. Verify only legacy examples disappear, user uploads and their runs remain, and repeating cleanup changes nothing. Review ambiguous retained records manually.
- [ ] **Upload and persistence:** upload permitted PDF, DOCX, TXT, CSV, PY, PNG, and JPG files. Restart the backend and confirm the same records and files remain. Unsupported, oversized, empty, and invalid filenames must be rejected. Duplicate filenames must preserve both files, including concurrent uploads.
- [ ] **Vault preview:** click a document name or Open. Check PDF navigation, PNG/JPG display, plain-text/CSV/Python previews, and DOCX paragraphs/tables. Download original must preserve the exact bytes; DOCX formatting and embedded images are available in the downloaded original. Check missing/corrupt files, long-text truncation, Escape/Close behavior, keyboard focus, and small screens. No external viewer may receive the source.
- [ ] **Vault deletion:** Cancel must preserve the document. Confirm Delete permanently for an approved disposable file; its row and source file must disappear and future knowledge searches must exclude it. Analysis history and generated reports remain accessible. Queued/running analyses must block deletion with a clear message; retry after completion. Check missing files, file-access failures, duplicate filenames, and persistence after reload/restart.
- [ ] **Source-based review:** analyze approved documents under each applicable domain profile. Every finding must quote that selected source, with correct page and text location. Documents with no matching issues must produce zero findings.
- [ ] **Real text inference:** run Summary with installed Ollama text models. Confirm the trace names the configured provider/model and the summary reflects the supplied file. Check cold-start latency, model timeout, empty output, and service/model absence; failures must be visible without fabricated text or successful reports.
- [ ] **Real vision:** analyze PNG/JPG/JPEG files in Summary, Risk review, and Extract fields, through both the fixed pipeline and planner. Inspect images must run in each case. Full visual observations must appear in Workbench, saved runs, and reports even when zero OCR fields match. Image summaries must preserve visual content when OCR also exists. Check transcription and uncertainty manually; unsupported/missing vision providers must fail explicitly, and visual observations must never be marked source-verified.
- [ ] **OCR:** test scanned and mixed-text PDFs, rotated/low-quality scans, and raster images with local Tesseract. Confirm page numbers, bounding boxes, OCR confidence, and review flags. Missing OCR dependencies must produce accurate guidance.
- [ ] **Review lifecycle:** high severity, low confidence, low OCR confidence, and unsupported evidence must remain held. Approve/reject decisions must persist; a run completes only after every required finding has a decision.
- [ ] **Failure display:** disconnect the backend on every page. Show unavailable/error states without substitute documents, reports, audit events, search results, or hardware readings. Reconnect and reload to restore real data.
- [ ] **Deployment boundary:** verify localhost bindings or authenticated proxy controls, TLS where needed, host firewall rules, file permissions, and disk encryption. The application does not supply authentication, RBAC, tamper-evident audit storage, or OS-level egress isolation.

## P1 - workflow and integration coverage

- [ ] **Literal extraction:** verify dates, currencies, owners, identifiers, measurements, and DOCX table values exactly match source text and citations.
- [ ] **Planner:** select a stored document and run the real local planner. Verify tool selection, prerequisites, maximum steps, loop protection, review holds, and normal completion with no findings. Missing/unknown document IDs must be rejected.
- [ ] **Workbench flow:** start a real PDF analysis. Confirm page/OCR activity appears during extraction and the configured model is visible during reasoning. Future stages must stay pending until executed; unnecessary stages must be marked skipped. Stage activity and elapsed time must reflect actual backend operations.
- [ ] **Inline results:** summary mode must display full model text directly in Workbench. Review and extraction modes must show source matches/fields, evidence, review buttons, and real report downloads without requiring a visit to Agent Runs. Verify reviewer decisions persist after reloading the page.
- [ ] **Reconnect and failures:** refresh during model inference, navigate away/back, and temporarily disconnect the backend. Workbench must reconnect to the same job ID without duplicate work. Model errors must preserve completed stages, mark the failing stage, and leave future stages unexecuted. Restart the backend mid-job and verify a clear interruption message. Full queues must return HTTP 429.
- [ ] **Knowledge search:** upload distinct readable documents, search their unique terms, and verify correct sources, pages, and ranking. Add/change a document, restart, and confirm the index refreshes. No prepared corpus should appear.
- [ ] **Learned embeddings:** select `KAVACH_EMBEDDING_BACKEND=provider` with a provisioned Ollama or Transformers encoder. Verify actual retrieval and visible outage errors. The index must never mix learned vectors with hash vectors after a failure.
- [ ] **Transformers:** provision local safetensors models and exercise real generation/embeddings. Missing paths, unsupported images, or missing dependencies must fail clearly. Confirm no Hub downloads or remote-code loading.
- [ ] **Reports:** download every enabled TXT, MD, DOCX, XLSX, and PDF variant. Open them in appropriate readers; check source content, pagination/layout, summary, citations, and review flags. Deleted report files must return a missing-file response. Reports are snapshots at generation time; compare subsequent review decisions in Agent Runs.
- [ ] **Audit trail:** perform upload, analysis, search, review, and download actions. Confirm local records describe actual actions and errors. Existing real audit events should survive example cleanup.
- [ ] **Monitoring:** compare available GPU readings with `nvidia-smi` and CPU/RAM with host tools. A host without GPU telemetry must show unavailable, not zero utilization. Configured model assignments must not be mistaken for health probes. Sandbox status must reflect the actual engine and runner image.
- [ ] **Python sandbox:** run code with stdin, syntax errors, and nonzero exits. Verify the worker UID is 65534, capabilities are absent, outbound sockets fail, host files/secrets are inaccessible, and the root filesystem is read-only. Temporary files must not survive the next job.
- [ ] **Sandbox limits and cleanup:** test an infinite loop, excessive output, memory allocation beyond the configured budget, process creation, and daemon loss. Verify timeouts, bounded output, useful failure states, and no leftover job containers. A second simultaneous request must receive HTTP 429. Run the opt-in real-container integration suite.
- [ ] **Sandbox request boundary:** verify remote clients, untrusted Origin/Host headers, missing execution headers, extra image/mount fields, blank/oversized code, oversized stdin, and excessive timeouts are rejected. No planner/tool action may execute a document automatically.
- [ ] **Docker:** build and start the stack on the target host, provision the actual models, upload/analyze a document, restart containers, and confirm DB/uploads/reports persist. Validate the shared network namespace, loopback inference access, local port bindings, and GPU configuration if used.

## P2 - reliability and release checks

- [ ] Exercise simultaneous uploads, analyses, searches, and review decisions at expected load. Measure memory use, SQLite contention, response times, and model queue behavior. Analysis requests are currently synchronous.
- [ ] Test missing files, malformed documents, unavailable storage, full disk, interrupted inference, and process restart. Verify useful errors and recoverable state.
- [ ] Verify backups and restore of SQLite, uploaded files, generated reports, and provisioned models. Validate the restored system using a document analysis and search.
- [ ] Review dependency versions and container image digests against the deployment's security requirements; run the organization's dependency scan before release.
- [ ] Check keyboard access, responsive layout, loading/error notices, and successful navigation across all pages in supported browsers.
- [ ] Run `python -m pytest -q`, `npx tsc --noEmit`, and `npm run build` on the release revision. Retain outputs and resolve new failures before deployment.
